# Detective Game — Документация проекта

> **Godot 4.2+ · GDScript · 2D · Русский язык**

Это кодовая основа детективной игры на движке Godot 4.  
В проекте уже реализованы все ключевые системы: главное меню, 15 локаций, 10 персонажей, система диалогов, дневник, сохранения, настройки звука и финальный тест. Тебе остаётся наполнить их сюжетом, рисунками и диалогами.

## 1. Быстрый старт

### Шаг 1 — Открыть проект в Godot 4.2+

1. Запусти Godot Engine версии **4.2 или новее**.
2. Нажми **Import** → выбери папку `detective_game`.
3. Дождись импорта ресурсов (первый раз занимает ~10 секунд).

### Шаг 2 — Добавить Autoload-синглтоны

Это самый важный шаг. Без него игра не запустится.

Открой: `Project → Project Settings → Autoload`

Добавь четыре записи **строго в этом порядке**:

| Имя в Autoload | Путь к файлу |
|---|---|
| `GameManager` | `res://autoload/GameManager.gd` |
| `SaveManager` | `res://autoload/SaveManager.gd` |
| `AudioManager` | `res://autoload/AudioManager.gd` |
| `DiaryManager` | `res://autoload/DiaryManager.gd` |

> **Порядок важен:** GameManager должен быть первым, потому что остальные три обращаются к нему при инициализации.

### Шаг 3 — Запустить игру

Нажми **F5** или кнопку Play. Должно открыться главное меню с кнопками «Новая игра», «Продолжить», «Настройки», «Выход».

## 3. Архитектура: как системы связаны

Чтобы понять проект, важно знать одну ключевую вещь: **четыре autoload-синглтона** — это мозг игры. Они всегда существуют в памяти и доступны из любого скрипта без import.

```
┌─────────────────────────────────────────────────────────┐
│                   AUTOLOAD (всегда в памяти)             │
│                                                          │
│  GameManager ←──────────────── состояние, переходы      │
│  SaveManager ←──────────────── файл сохранения          │
│  AudioManager ←─────────────── громкость, музыка        │
│  DiaryManager ←─────────────── локации, персонажи, улики│
└─────────────────────────────────────────────────────────┘
         ↑ ↑ ↑ ↑   (каждый скрипт может обращаться к ним)

┌──────────────┐    ┌────────────────────────────────────┐
│  MainMenu    │    │  LocationBase (активная локация)   │
│              │    │  ├─ DialogueBox                    │
│  [Новая игра]│───▶│  ├─ PauseMenu + Settings           │
│  [Продолжить]│    │  ├─ Diary                          │
│  [Настройки] │    │  └─ CharacterBase × N              │
│  [Выход]     │    └────────────────────────────────────┘
└──────────────┘
```

**Поток событий при запуске новой игры:**
1. Игрок нажимает «Новая игра» → `MainMenu.gd` вызывает `GameManager.start_new_game()`
2. `GameManager` сбрасывает `DiaryManager`, удаляет сохранение, загружает `Location01.tscn`
3. `Location01` в `_ready()` регистрирует себя в дневнике, загружает фон, подключает кнопку дневника
4. Игрок кликает по персонажу → `CharacterBase._interact()` запускает диалог через `LocationBase.start_dialogue()`
5. `DialogueBox` воспроизводит текст → по завершении `DiaryManager.complete_dialogue()` записывает диалог в дневник
6. Игрок нажимает Escape → `LocationBase._input()` открывает `PauseMenu`
7. Игрок выбирает «Выход» → `PauseMenu` вызывает `GameManager.quit_game()` → `SaveManager.auto_save()` → `get_tree().quit()`

## 4. Autoload-синглтоны (мозг игры)

### `GameManager.gd`

Главный менеджер состояния. Знает, где сейчас находится игрок и в каком состоянии игра.

**Состояния игры (`GameState`):**

| Состояние | Когда активно |
|---|---|
| `MAIN_MENU` | В главном меню |
| `PLAYING` | На локации, ничего не происходит |
| `DIALOGUE` | Идёт диалог |
| `PAUSED` | Открыто меню паузы |
| `DIARY` | Открыт дневник |
| `ENDING` | Финальный экран |

**Ключевые методы:**

```gdscript
GameManager.start_new_game()           # Начать с нуля
GameManager.continue_game()            # Загрузить сохранение
GameManager.travel_to_location("Location03")  # Перейти на локацию
GameManager.return_to_main_menu()      # Вернуться в меню (+ автосохранение)
GameManager.quit_game()                # Выход (+ автосохранение)
GameManager.complete_story()           # Завершить сюжет → разблокирует тест
```

**Переменные:**

```gdscript
GameManager.current_location   # String: "Location01" — текущая локация
GameManager.game_started        # bool: игра запущена
GameManager.story_completed     # bool: сюжет завершён → тест в дневнике доступен
GameManager.current_state       # GameState: текущее состояние
```

---

### `SaveManager.gd`

Управляет файлом сохранения. Сохранение хранится в:
- **Windows:** `%APPDATA%\Godot\app_userdata\Detective Game\savegame.save`
- **Linux/Mac:** `~/.local/share/godot/app_userdata/Detective Game/savegame.save`

Формат файла: обычный JSON, можно открыть блокнотом.

**Что сохраняется:**
- Текущая локация
- Завершён ли сюжет
- Все данные дневника (открытые персонажи, улики, диалоги)
- Настройки громкости

**Автосохранение происходит автоматически при:**
- Выходе в главное меню
- Выходе из игры
- Переходе с одной локации на другую

Вручную вызывать `SaveManager.auto_save()` нужно только если ты добавляешь свои точки сохранения.

```gdscript
SaveManager.has_save()     # → true, если файл сохранения существует
SaveManager.clear_save()   # Удалить сохранение (вызывается при "Новая игра")
```

---

### `AudioManager.gd`

Управляет тремя аудиошинами: **Master** (общая), **Music** (музыка), **SFX** (эффекты).

> Шины создаются автоматически при первом запуске — вручную ничего настраивать не нужно.

**Как воспроизвести музыку на локации:**

```gdscript
# В скрипте локации:
@export var location_music: AudioStream
# Назначь файл в инспекторе → LocationBase автоматически запустит его в _ready()
```

**Как воспроизвести звуковой эффект:**

```gdscript
var sfx: AudioStream = preload("res://assets/sounds/click.ogg")
AudioManager.play_sfx(sfx)
```

**Настройки громкости** хранятся в сохранении и восстанавливаются при загрузке.

---

### `DiaryManager.gd`

Хранит всё, что игрок узнал: локации, персонажей, улики, диалоги. Это единственное место, где живут все игровые данные.

**Структура данных персонажа:**

```gdscript
DiaryManager.characters["character_01"] = {
    "name":           "Виктор",
    "surname":        "Ларин",
    "info":           "Хозяин особняка, 58 лет.",
    "motive":         "(заполняется по сюжету)",
    "alibi":          "(заполняется по сюжету)",
    "photo_path":     "res://assets/characters/character_01.png",
    "interrogations": [],   # Список строк с записями допросов
    "discovered":     false # true = появился в дневнике
}
```

**Структура данных улики:**

```gdscript
DiaryManager.evidence["evidence_01"] = {
    "title":          "Стакан с ядом",
    "description":    "Хрустальный стакан со следами отравляющего вещества.",
    "location_found": "Библиотека",
    "circumstances":  "Найден за книжным шкафом во время осмотра.",
    "discovered":     false
}
```

**Ключевые методы:**

```gdscript
DiaryManager.discover_character("character_03")    # Открыть персонажа в дневнике
DiaryManager.find_evidence("evidence_02")          # Открыть улику в дневнике
DiaryManager.add_interrogation("character_03", "Отрицал свою причастность") # Добавить запись допроса
DiaryManager.complete_dialogue("dlg_library_01")   # Пометить диалог как завершённый
```

## 5. Сцены и скрипты

### `LocationBase.gd` — базовый класс всех локаций

Каждая из 15 локаций наследует этот класс. Он берёт на себя:
- Регистрацию локации в дневнике
- Загрузку фонового изображения
- Обработку Escape (пауза)
- Обработку кликов ЛКМ
- Запуск и завершение диалогов
- Кнопку «Дневник»

**Экспортируемые переменные** (настраиваются в Инспекторе):

```gdscript
@export var location_id:        String       # Уникальный ID, например "location_03"
@export var location_name:      String       # Отображаемое название
@export var location_music:     AudioStream  # Фоновая музыка (опционально)
@export var background_texture: Texture2D   # PNG-фон (или назначь в .gd через preload)
@export var exits: Dictionary               # Переходы: { "метка" -> "LocationXX" }
```

**Методы для переопределения в дочерних скриптах:**

```gdscript
func _setup_location() -> void:
    # Вызывается в _ready(). Подключай Area2D-зоны и настраивай логику здесь.
    pass

func _on_scene_clicked(pos: Vector2) -> void:
    # Вызывается при каждом клике ЛКМ по экрану (не по Area2D-зонам).
    pass
```

---

### `CharacterBase.gd` — базовый класс всех персонажей

Каждый из 10 персонажей наследует этот класс. Он берёт на себя:
- Отображение спрайта
- Обработку клика по персонажу (через Area2D)
- Автоматическое открытие персонажа в дневнике при первом клике
- Последовательное воспроизведение диалогов

**Переменная для диалогов:**

```gdscript
var dialogues: Array = []
# Заполни в _setup_character() — см. раздел «Как написать диалог»
```

**Как работает последовательность диалогов:**  
При каждом клике по персонажу запускается следующий диалог из массива `dialogues`. Когда все диалоги сыграны, снова запускается последний. Это позволяет вести разговор поэтапно: первый клик — приветствие, второй — вопрос об алиби, третий — улика и т.д.

---

### `DialogueBox.gd` — система диалогов

Отвечает за весь визуальный вывод диалогов. Работает поверх любой локации.

**Как работает:**
1. Локация вызывает `start_dialogue(data)` → DialogueBox становится видимым
2. Текст выводится посимвольно (эффект печатной машинки)
3. **ЛКМ во время печати** → весь текст реплики показывается сразу
4. **ЛКМ после окончания реплики** → переход к следующей реплике
5. После последней реплики DialogueBox скрывается, диалог записывается в дневник

**Скорость печати** задаётся через `@export var char_delay: float = 0.03` (секунды на символ). Можно изменить в Инспекторе для конкретного DialogueBox или через код.

---

### `PauseMenu.gd` — меню паузы

Открывается нажатием **Escape** на любой локации.  
Содержит: **Продолжить / Настройки / Главное меню / Выход**.  
При выборе «Главное меню» и «Выход» — автоматически сохраняет игру.

---

### `Diary.gd` — дневник следователя

Открывается кнопкой «Дневник» в правом верхнем углу экрана.

**Три вкладки:**
- **Локации** — список всех посещённых локаций
- **Персонажи** — карточки открытых персонажей (фото, имя, мотив, алиби, допросы, все диалоги с ним)
- **Улики** — список найденных улик с описанием

Персонаж появляется в дневнике автоматически при **первом клике** по нему.  
Диалог появляется в дневнике автоматически при **завершении** (последняя реплика).  
Улика появляется при вызове `DiaryManager.find_evidence()`.

**Кнопка «ПРОВЕСТИ ФИНАЛЬНЫЙ ТЕСТ»** — скрыта до вызова `GameManager.complete_story()`.

---

### `Settings.gd` — настройки звука

Панель с тремя слайдерами: Общая громкость / Музыка / Эффекты.  
Используется и в главном меню, и в меню паузы — это одна и та же сцена `Settings.tscn`, которая инстансируется в обоих местах.

---

### `EndingTest.gd` — финальный тест

Открывается из дневника кнопкой «Финальный тест» после завершения сюжета.  
Три выпадающих списка: **кто убийца / метод / мотив**.  

**Правильные ответы задаются в Инспекторе** сцены `EndingTest.tscn`:

```
correct_killer_id = "character_03"     # ID убийцы (из DiaryManager.characters)
correct_method    = "Отравление"       # Должно точно совпадать с текстом в списке
correct_motive    = "Деньги / наследство"
```

Или можно задать через код перед открытием теста:

```gdscript
ending_test_instance.correct_killer_id = "character_03"
ending_test_instance.correct_method    = "Отравление"
ending_test_instance.correct_motive    = "Деньги / наследство"
```

## 6. Как добавить фон локации

**Вариант А — через Инспектор:**
1. Открой сцену `scenes/locations/LocationXX.tscn`
2. Выдели узел `Background (Sprite2D)`
3. В Инспекторе → `Texture` → нажми на поле → выбери свой PNG

**Вариант Б — через код (уже сделано в шаблоне):**

```gdscript
# В файле scenes/locations/LocationXX.gd:
func _ready() -> void:
    background_texture = preload("res://assets/locations/location_01.png")
    super._ready()   # ← НЕ ЗАБУДЬ это вызвать! Иначе ничего не сработает.
```

> **Важно:** Всегда вызывай `super._ready()` в дочерних скриптах локаций. Это запускает всю инициализацию `LocationBase`: регистрацию в дневнике, загрузку фона, подключение кнопки дневника и т.д.

## 7. Как добавить персонажа на локацию

### Шаг 1 — Создать экземпляр сцены персонажа

1. Открой нужную `LocationXX.tscn`
2. Выдели узел `Characters`
3. Нажми ПКМ → **Instantiate Child Scene**
4. Выбери `scenes/characters/CharacterXX.tscn`

### Шаг 2 — Расположить персонажа

Перетащи узел персонажа в нужную точку сцены.

### Шаг 3 — Настроить CollisionShape2D

Выдели `CollisionShape2D` внутри `CharacterXX → ClickArea` и подгони размер прямоугольника под спрайт персонажа.

### Шаг 4 — Добавить диалоги

Открой `scenes/characters/CharacterXX.gd` и заполни метод `_setup_character()`.  
Пример уже есть в каждом файле персонажа — просто замени текст.

## 8. Как написать диалог

### Формат диалога

```gdscript
var dialogue = {
    "id":           "dlg_library_sokolov_01",  # Уникальный ID
    "character_id": "character_03",             # С кем разговор
    "lines": [
        {
            "speaker":       "Дмитрий Соколов",
            "text":          "Добрый день, инспектор. Чем могу помочь?",
            "portrait_path": "res://assets/characters/character_03_portrait.png"
        },
        {
            "speaker":       "Инспектор",
            "text":          "Расскажите, где вы были в ночь убийства.",
            "portrait_path": ""   # Пустая строка = портрет не показывается
        },
        {
            "speaker":       "Дмитрий Соколов",
            "text":          "Я... я был здесь, в библиотеке. Один.",
            "portrait_path": "res://assets/characters/character_03_portrait.png"
        },
    ]
}
```

### Использование вспомогательного класса DialogueData

Для удобства можно использовать класс из `resources/DialogueData.gd`:

```gdscript
var dialogue = DialogueData.make_dialogue(

        DialogueData.line("Дмитрий Соколов", "Добрый день!", "res://assets/characters/character_03_portrait.png"),

```

### Добавить несколько диалогов к персонажу

Диалоги воспроизводятся последовательно: первый клик = первый диалог, второй клик = второй и т.д.

```gdscript
# В CharacterXX.gd:
func _setup_character() -> void:
    character_id = "character_03"
    character_sprite = preload("res://assets/characters/character_03.png")

    dialogues = [
        DialogueData.make_dialogue("dlg_sokolov_01", "character_03", [

            DialogueData.line("Соколов", "Я уже сказал всё, что знал."),
            DialogueData.line("Инспектор", "Мне нужна правда о той ночи."),
            DialogueData.line("Соколов", "...Хорошо. Я расскажу."),

```

### Обновить мотив/алиби персонажа в ходе диалога

Если в процессе диалога раскрывается новая информация — обнови данные в `DiaryManager`:

```gdscript
# Добавить запись допроса:
DiaryManager.add_interrogation("character_03", "Признал, что был в библиотеке около полуночи.")

# Обновить алиби:

```

## 9. Как добавить улику

### Шаг 1 — Задать описание улики в DiaryManager

Открой `autoload/DiaryManager.gd`, найди метод `_init_evidence()` и заполни нужную запись:

```gdscript
evidence["evidence_01"] = {
    "title":          "Стакан с ядом",
    "description":    "Хрустальный стакан со следами мышьяка.",
    "location_found": "Библиотека",
    "circumstances":  "Найден за вторым томом энциклопедии.",
    "discovered":     false,
}
```

### Шаг 2 — Создать кликабельную зону в сцене локации

1. Открой сцену локации (например `Location02.tscn`)
2. Выдели узел `InteractiveAreas`
3. Добавь дочерний `Area2D`, назови его `EvidenceStakana`
4. Внутри добавь `CollisionShape2D` нужной формы
5. Опционально: добавь `Sprite2D` или `TextureRect` с изображением объекта

### Шаг 3 — Подключить зону к обнаружению улики

В скрипте локации `Location02.gd`:

```gdscript
func _setup_location() -> void:
    $InteractiveAreas/EvidenceStakana.input_event.connect(
        func(_viewport, event, _shape):
            if event is InputEventMouseButton and event.pressed:
                DiaryManager.find_evidence("evidence_01")
                # Можно также показать диалог:
                # start_dialogue({ "id": "dlg_found_glass", ... })
    )
```

## 10. Как настроить переходы между локациями

Переход — это кликабельная зона, при нажатии на которую загружается другая локация.

### Шаг 1 — Создать зону перехода

1. Открой сцену локации
2. Добавь `Area2D` в узел `InteractiveAreas`, назови `ExitToLibrary`
3. Внутри добавь `CollisionShape2D` (прямоугольник вдоль двери/прохода)

### Шаг 2 — Подключить через код

```gdscript
# В LocationXX.gd:
func _setup_location() -> void:
    $InteractiveAreas/ExitToLibrary.input_event.connect(
        func(_viewport, event, _shape):
            if event is InputEventMouseButton and event.pressed:
                travel_to("Location02")   # Имя файла без .tscn
```

## 11. Система сохранений

Сохранение происходит **автоматически** — вручную ничего нажимать не нужно.

**Когда сохраняется:**
- При нажатии «Главное меню» в паузе
- При нажатии «Выход» в паузе
- При переходе с одной локации на другую

**Что хранится в файле сохранения** (JSON):

```json
{
  "current_location": "Location03",
  "story_completed": false,
  "timestamp": "2025-05-20 14:33:21",
  "audio_settings": {
    "master_volume": 1.0,
    "music_volume": 0.8,
    "sfx_volume": 1.0
  },
  "diary_data": {
    "discovered_locations": ["location_01", "location_02", "location_03"],
    "characters": { ... },
    "evidence":   { ... },
    "dialogue_history": { ... }
  }
}
```

**Кнопка «Продолжить»** в главном меню активна только если файл сохранения существует. При «Новой игре» — файл удаляется.

Дневник автоматически пополняется без каких-либо дополнительных вызовов:

| Что происходит в игре | Что появляется в дневнике |

## 13. Финальный тест

Когда сюжет завершён, вызови:

```gdscript
GameManager.complete_story()
```

После этого в дневнике, в карточке любого персонажа, появится кнопка **«ПРОВЕСТИ ФИНАЛЬНЫЙ ТЕСТ»**.

Тест задаёт три вопроса: кто убийца / каким способом / из-за чего. Ответы проверяются по полям `correct_killer_id`, `correct_method`, `correct_motive` в скрипте `EndingTest.gd`.

**Чтобы задать правильные ответы**, открой `scenes/ui/EndingTest.tscn` в редакторе, выдели корневой узел `EndingTest` и в Инспекторе измени значения `Correct Killer Id`, `Correct Method`, `Correct Motive`.

Список убийц в тесте формируется автоматически из персонажей, которых игрок открыл в дневнике. Метод и мотив — из жёстко заданных списков в `EndingTest.gd` (константы `METHODS` и `MOTIVES`). При необходимости отредактируй эти массивы под свой сюжет.

## 18. Часто задаваемые вопросы

**Q: Нажал F5, игра вылетает с ошибкой «GameManager is not a valid class»**  
A: Не добавлены Autoload-синглтоны. Смотри раздел «Быстрый старт → Шаг 2».

**Q: Клик по персонажу не открывает диалог**  
A: Проверь, что `CollisionShape2D` внутри `ClickArea` персонажа имеет заданную форму (Shape не пустой). Также убедись, что массив `dialogues` в `_setup_character()` не пустой.

**Q: После диалога текст не появляется в дневнике**  
A: Убедись, что у диалога уникальный `id` — две разных записи с одинаковым id перезапишут друг друга.

**Q: Хочу сделать диалог, который запускается не по клику на персонажа, а при входе на локацию**  
A: В `_setup_location()` локации добавь вызов через `call_deferred`:
```gdscript
func _setup_location() -> void:
    call_deferred("start_dialogue", мой_диалог)
```
`call_deferred` нужен, чтобы дождаться полной инициализации сцены.

**Q: Хочу сделать диалог, который запускается только один раз**  
A: Храни флаг в переменной класса:
```gdscript
var _intro_played := false

func _setup_location() -> void:
    if not _intro_played:
        _intro_played = true
        call_deferred("start_dialogue", intro_dialogue)
```
Для сохранения флага между сессиями — добавь его в `SaveManager.auto_save()`.

**Q: Можно ли показать диалог без привязки к персонажу (внутренний монолог инспектора)?**  
A: Да. Вызови `start_dialogue()` прямо из локации:
```gdscript
start_dialogue({
    "id": "dlg_monologue_01",
    "character_id": "",   # Пустая строка — без привязки
    "lines": [
        { "speaker": "Инспектор (мысли)", "text": "Здесь что-то не так...", "portrait_path": "" }
    ]
})
```

**Q: Кнопка «Финальный тест» не появляется в дневнике**  
A: Нужно вызвать `GameManager.complete_story()`. До этого кнопка скрыта намеренно.

**Q: Где физически хранится файл сохранения?**  
A: 
- Windows: `C:\Users\<Имя>\AppData\Roaming\Godot\app_userdata\Detective Game\savegame.save`
- Linux: `~/.local/share/godot/app_userdata/Detective Game/savegame.save`  
- macOS: `~/Library/Application Support/Godot/app_userdata/Detective Game/savegame.save`
